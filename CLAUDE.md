# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`@blen/uspto-mcp-server` — a "code-mode" MCP server for the USPTO APIs: the Open Data Portal (`odp.*`, `api.uspto.gov`: patent file wrapper, PTAB, petitions, office actions, bulk-dataset catalog) and TSDR trademark status (`tsdr.*`, `tsdrapi.uspto.gov`). `developer.uspto.gov` now redirects to the Open Data Portal. Instead of dozens of narrow tools it exposes exactly three — `search_api`, `describe_schema`, `execute` — and lets the model write JavaScript that runs in a locked-down sandbox with one global per source. Transports: stdio (default), Streamable HTTP (`--http`), and account mode (`--http` + `USPTO_AUTH_PROVIDER=accounts`: Google sign-in, per-user encrypted keys). Derived from the sibling `fedreg-mcp-server`; the transport, sandbox, search and accounts layers are shared design (the sandbox and auth hardening here is newer than the sibling's).

## Commands

Run everything from this directory (`pnpm@10.33.0` pinned via `packageManager`; Node 24 or 26):

```bash
pnpm install
pnpm typecheck                          # tsc --noEmit (src + test) and web/tsconfig — THE correctness gate
pnpm test                               # vitest run (all test/*.spec.ts, ~15 s, no network/keys needed)
pnpm test test/search.spec.ts           # single file (args forward to vitest, no -- needed)
pnpm test test/search.spec.ts -t "bm25" # single test by name (pair with file path to keep it fast)
pnpm lint                               # eslint . — minimal config (unused-vars only); passing means little
pnpm build                              # tsc -p tsconfig.build.json && pnpm build:web (Vite → dist/web) && chmod
pnpm dev                                # tsx src/bin.ts (stdio)
pnpm dev --http --insecure              # HTTP transport, no auth, binds 127.0.0.1; also --port, --host, --sandbox
USPTO_LIVE=1 pnpm test:live             # opt-in live acceptance against USPTO (needs USPTO_API_KEY; never in PR CI)
node scripts/gen-sdk-reference.mjs      # regenerate the method section of docs/sdk-reference.md from schema/*.json
node scripts/capture-samples.mjs <dir>  # (after pnpm build, with USPTO_API_KEY) capture live ODP sample responses
node scripts/gen-fields.mjs --source live=<dir> --source patent-dev=<dir>   # regenerate the field dictionary
node scripts/mcpb-smoke.mjs <unpacked-bundle-dir>                           # execute('return 42') in an unpacked MCPB
```

- In `pnpm build`, the `|| true` guards only the `chmod` — a `tsc` failure DOES fail the build. `pnpm typecheck` remains the broader gate (it also covers `test/**`, which the build config excludes).
- CI (`.github/workflows/ci.yml`) runs `pnpm audit --audit-level moderate`, `typecheck`, `lint`, `build`, `test` on Node 24 and 26 with Postgres and Deno and `USPTO_REQUIRE_RUNNERS=1`, plus an npm-package/MCPB smoke job and a Docker job (refuses to start without auth; runs `execute` in the Deno sandbox). The PR template requires the four gates as checkboxes.
- Sandbox and account tests skip when their dependency is missing (no runner / no `TEST_DATABASE_URL`). `test/required-runners.spec.ts` turns those skips into failures when `USPTO_REQUIRE_RUNNERS=1` (CI), so a green CI run means they actually ran. Locally, a throwaway Postgres works:
  `docker run -d --rm --name uspto-mcp-test-pg -e POSTGRES_PASSWORD=uspto-ci -e POSTGRES_DB=uspto_test -p 127.0.0.1:55432:5432 postgres:16-alpine`
  then `TEST_DATABASE_URL=postgres://postgres:uspto-ci@127.0.0.1:55432/uspto_test USPTO_REQUIRE_RUNNERS=1 pnpm test` (needs Deno on PATH).

### Environment notes

- `isolated-vm` 7 ships prebuilt binaries for Node 24 (ABI 137) and 26 (ABI 147) on darwin-arm64, linux-x64/arm64 (glibc + musl) and win32-x64; `node-gyp-build` loads them at runtime, so no compiler is needed and `--ignore-scripts` installs still work. Deno (2.7.x) is the other runner; if installed to `~/.deno/bin`, prefix commands with `PATH="$HOME/.deno/bin:$PATH"`.
- **TypeScript 7 runs side by side with TS 6** (the TS 7 announcement's documented setup): `devDependencies.typescript` is `npm:@typescript/typescript6` (the 6.0 API that typescript-eslint and other tooling import) and `@typescript/native` is `npm:typescript@^7`, which provides the `tsc` binary (`npx tsc --version` → 7.x). typescript-eslint refuses TS 7's API; don't "simplify" the aliases away.
- Live calls need keys: `USPTO_API_KEY` (ODP, sent as `X-API-KEY`) and `USPTO_TSDR_API_KEY` (TSDR, sent as `USPTO-API-KEY`; a separate key — the ODP key is rejected by TSDR). The ODP key needs a USPTO.gov account with MFA plus a one-time ID.me link (https://data.uspto.gov/support/universal-registration); keys of accounts missing the profile fields required since 2026-08-18 were deactivated on 2026-10-08 and return 403 until reactivated ("Activate API Key"). Never print or commit keys; `.env` is gitignored and is NOT loaded by the server (`set -a; . ./.env; set +a`).
- Build-script approval for esbuild/isolated-vm lives in `pnpm-workspace.yaml` (`allowBuilds:`), together with `overrides:` that pin patched transitive versions for dev tooling (pnpm audit). Remove an override once its parent ships the fix. Don't move these to package.json and don't casually bump the pnpm major.

## Architecture

Request flow (all transports converge on the same tool catalog):

```
stdio | Streamable HTTP (+OAuth, Host/Origin, per-IP bucket, quotas) | accounts   src/server/{stdio,http}.ts, src/accounts/
  -> buildMcpServer (SDK v2 McpServer, registerTool + outputSchema)            src/server/mcpServer.ts, toolCatalog.ts
  -> tools: searchApi | describeSchema | execute (admission, budgets, cancel)   src/tools/
  -> execute: AST preflight -> sandbox runner (byte budgets, host deadline)    src/sandbox/{policy,limits,isolate,deno}.ts
  -> sandbox globals (odp/tsdr Proxies) --RPC bridge--> dispatch()             src/sdk/runtime.ts
  -> per-source HttpClient (key gate + LRU + retry + caps + redaction)         src/util/{httpClient,upstreamGate}.ts
  -> api.uspto.gov / tsdrapi.uspto.gov
```

`buildSupervisor(cfg)` in `src/supervisor/index.ts` is the single composition root: it builds ONE set of sources (shared by the corpus and dispatch via `sdkFromSources`), one gate and one hourly `TokenBucket` per configured key, the corpus, the sandbox (`pickSandbox(kind, { processIsolation })`), the `ExecutionLimiter`, and per-source `callBudgets` / `subjectQuotas`, and returns `CatalogDeps`, which everything downstream receives by injection. `LIMIT_DEFAULTS` and `EXECUTION_DEFAULTS` there hold the defaults. All env vars are read in `src/bin.ts` (plus `USPTO_LOG_LEVEL` in the logger; account settings are read from the `env` object bin.ts passes to `loadAccountConfig`) — nothing else touches `process.env`, and there is no dotenv: `.env.example` is documentation only.

**Source registry** (`src/sdk/sources/`): each source is a factory returning `{ name, label, enabled, disabledReason?, client, methods, corpus }`. The frozen `methods` table explicitly registers public SDK methods; dispatch never traverses `client` or its internals (so private helpers like `OdpClient.search`/`list`/`dsapi`/`app` are unreachable). Adding a source = one factory + one line in `getSources()` + a `schema/<name>.json` corpus file. Source names are validated at boot as safe JS identifiers (they get interpolated into generated sandbox code — the validation is the security precondition). Both sources are key-gated: without a key they are still registered (the sandbox global exists and the corpus stays searchable) but dispatch returns `SourceUnavailable` instead of a `ReferenceError`. This is by design and tested — don't "fix" it.

**SDK clients** (`src/sdk/{odp,tsdr}-client.ts`): identifiers go through grammars before reaching a path (`normalizeApplicationNumber`, `segment()` = `^[A-Za-z0-9][A-Za-z0-9._-]{0,199}$`, so `.`/`..`/separators can never change the endpoint; TSDR `normalizeCaseId`: `sn`+8 digits, `rn`, `ir`, `ref`+alphanumeric). ODP answers an empty query with **HTTP 404 + "No matching records found"**; `emptyOnNoMatches` maps that to `{ count: 0, <bag>: [] }` for searches and list endpoints (`byTrial`, `byAppeal`, …), while get-by-id keeps `NotFound`. `petitions.get` takes only the id (records always include `documentBag`; there is no `includeDocuments`).

**Keys**: each key lives host-side in a private `HttpClient` field (`#defaultHeaders`) and must never appear on `Source` objects, logs, error messages, or `JSON.stringify` output — tests assert this. `HttpClient` also scrubs any configured key an upstream echoes back: in raw text, in decoded JSON values and object keys (JSON escapes can spell a key the raw scan misses), and in error messages, in every mode. The cache key folds headers (including the key) into a digest.

**Corpus** (`schema/{odp,tsdr}.json`): `search_api`/`describe_schema` only surface what's in these files. Endpoint entries are hand-written (one per registered method; `test/sources.spec.ts` asserts the ids equal the methods tables exactly; `test/corpus.spec.ts` parses every `example` with acorn, runs it through the real preflight, and checks it only calls registered methods; `pnpm test:live` runs every ODP example against USPTO). Field entries with ids `<binding>.fields.*` are GENERATED by `scripts/gen-fields.mjs` from the samples listed in `scripts/field-samples.json` — ODP from live captures (`scripts/capture-samples.mjs`), TSDR from patent-dev/uspto-odp samples until a TSDR key exists. The generator validates the whole manifest before writing anything, writes atomically, records a `provenance` block (sources, file sha256s) in each schema file, emits per-family query guidance (ODP search body vs legacy DSAPI criteria), and never emits example values for personal-data or free-text fields. Never hand-edit a `*.fields.*` entry — regenerate. `docs/sdk-reference.md`'s method section is generated from the same files (`scripts/gen-sdk-reference.mjs`; `test/corpus.spec.ts` fails when it is stale). BM25 penalizes long documents, so keep endpoint descriptions focused (shared search syntax lives once, in `odp.syntax.search`); `test/search.spec.ts` has natural-language retrieval cases. The corpus is loaded via `readFileSync(resolve(__dirname, '../../../schema/...'))` — `schema/` must ship as a sibling of `dist/`.

**Sandbox** (`src/sandbox/`): an acorn AST preflight (`policy.ts`, bans imports/eval/`process`/`globalThis`/`Deno`/`fetch`/`constructor`/`__proto__`/etc.), then a runner. Both runners: user code wrapped in `(async () => { ... })()` (top-level `await`/`return` legal), a **host-owned wall-clock deadline** that starts before setup and also covers never-settling promises, the execution's `AbortSignal`, and byte budgets from `limits.ts` (code 256 KiB, result 256 KiB → `ResultTooLarge`, logs 64 KiB / 1000 lines with 16 B per-line overhead, RPC args 64 KiB, 16 pending calls) enforced **inside the sandbox before anything is transferred** and again on the host. SDK errors keep `name`/`message`/`status` across the boundary. The preflight parses plain JavaScript — TypeScript syntax is a `PolicyError`; `test/examples.spec.ts` keeps `examples/*.js` pasteable.
- `isolate.ts`: fresh `isolated-vm` isolate per execution (heap cap = `memoryMb`), disposed on deadline/abort; results tagged `V`/`E`/`R` so status and oversize survive the copy.
- `deno.ts`: `deno run --no-prompt --no-config --no-lock --no-remote --no-npm` of a FIXED supervisor script (written once per process to a 0700 temp dir; it never contains user code) with no `--allow-*` flags and a minimal env. The supervisor announces a random token, receives the code in a stdin frame, and runs it in a module Worker whose `Deno`, `postMessage`, `fetch`, `Worker`, … globals are replaced with `undefined` and whose `console` posts log messages. Frames are token-prefixed JSON lines; anything else on stdout is untrusted log text. The parent owns the deadline, kills the process group, and resolves only after the child has exited (bounded 2 s). `--v8-flags=--max-old-space-size` applies `memoryMb`.
- `pickSandbox` (`index.ts`): `auto` prefers isolated-vm for single-user use (stdio, `--insecure`). With `processIsolation` (authenticated `--http`, incl. accounts — set in bin.ts as `http && !insecure`) only Deno is allowed: `--sandbox isolate` throws at startup, and `auto` without Deno yields an `UnavailableRunner` (execute reports why) — never a silent fallback to in-process execution.

**execute** (`src/tools/execute.ts`): refuses to start if the request or server is already aborted; admission via `ExecutionLimiter` (8 global / 2 per subject by default; `Busy` beyond); a per-execution `AbortController` combines the MCP request's `ctx.mcpReq.signal` (client cancel/disconnect), the shutdown signal, and the end of the execution, and reaches the HTTP client through `AsyncLocalStorage` (`src/util/executionContext.ts`) — so queued and in-flight upstream calls stop. Per-binding call budgets (ODP 50, TSDR 25), per-subject hourly quotas (HTTP only).

**HTTP transport** (`src/server/http.ts`): MCP `2026-07-28` — stateless, no `initialize` handshake, no `Mcp-Session-Id`. `createMcpHandler` builds a fresh `McpServer` + tool catalog **per request**, so the subject a tool sees always comes from that request's own bearer token. Pre-2026 clients are served by the SDK's stateless legacy fallback, and `GET`/`DELETE /mcp` return 405. It fails closed: `--http` without `--insecure` refuses to start unless an OIDC provider (`generic-oidc`/`clerk`/`workos`/`auth0`) or `accounts` is configured; unknown providers stop startup; OIDC requires issuer + audience + JWKS (https, or http on loopback), verifies `exp`/`sub`, asymmetric algorithms only, and every `USPTO_AUTH_SCOPES` scope (403 `insufficient_scope`). Trusted hosts come from `USPTO_PUBLIC_ORIGIN`/`USPTO_ALLOWED_HOSTS` plus loopback on the listening port — never from the request's Host; binding non-loopback without either is a startup error (`*` disables the check). Bodies are capped at 1 MiB (`MAX_REQUEST_BODY_BYTES`), tool arguments at `MAX_TOOL_INPUT_ELEMENTS`. `--insecure` defaults the bind address to 127.0.0.1. stdio has no auth and no subject, so per-subject quotas are skipped there.

**Account mode** (`src/accounts/`, `web/`, docs/accounts.md): `/mcp` is anonymous and registers ONLY `search_api` + `describe_schema` (`publicDependencies` sets `tools`; a direct `execute` call is "Tool not found"). `/mcp/account` (OAuth) is the only place code runs. Account mode never uses process-level keys for anyone (USPTO: "Do not share it with others"); `accountDependencies` strips them and swaps in per-user methods that lazily load ONLY the key for the source being called (`credentials` PK `(owner, kind)`, kind `odp`|`tsdr`, AES-GCM context `uspto-<kind>:<owner>`), build a cached client per owner+kind+key, and redact the key from results and errors. Admission is per **credential** (`keyGates.ts`: one gate per digest(kind, key), resolved per request through `gateHandle`, shared with key checks; idle gates retired at 1000 entries). Key checks need a 2xx (ODP probe: status-codes; TSDR probe: casestatus `sn97123456`, because TSDR answers a bad key with 404 and last-update answers 204 even without a key) and honor 429 cooldowns. DCR registrations whose redirect URIs are all loopback HTTP get `application_type: native` (better-auth follows OpenID DCR, which otherwise demands https). Signed-in calls always hit the official hosts — base-URL overrides never apply.

**Guardrails** (in-memory per process, except account-mode hourly limits in PostgreSQL): per-key gate (concurrency 1, ODP 4/s, TSDR 1/s, burst 1, `maxWaitMs` 30 s) → hourly budget charged per real attempt after gate admission → per-execute call budget → per-subject hourly quota. On a 429 the gate is paused for max(5 s, Retry-After) **from status and headers, before the body is read and before the slot is released**; the full Retry-After is honored (sanity cap 8 days, so a weekly-quota reset days away is respected), and the call itself is retried once only if that cooldown is ≤ 30 s. 5xx/network errors retry with backoff (`USPTO_UPSTREAM_RETRIES`). gunzip expansion is bounded (`maxOutputLength`). A rate of `0` would mean "block everything", not "unlimited" — `src/bin.ts` replaces any hourly/concurrency value < 1 with the default; disable a source by unsetting its key.

**Results and errors** (MCP SDK v2, verified on the wire):
- Tool results are compact JSON text plus the same object as `structuredContent`, validated against the tool's `outputSchema` (`OUTPUT_SCHEMAS` in toolCatalog.ts).
- A failed `execute` (`ok: false`: thrown error, timeout, limit, `Busy`) returns `isError: true` WITH the full envelope `{ ok, error: { name, message, status? }, logs, durationMs }`.
- `isError: true` also appears for a thrown handler exception and for argument-validation failures (the SDK's Ajv validator; input schemas come from Zod 4's `z.toJSONSchema` with `additionalProperties: false`, real integer/min/max/length constraints, and a `oneOf` for describe_schema's path|prefix rule).
- An **unknown tool name is not a tool result** — it surfaces as a JSON-RPC error `{"error":{"code":-32602,"message":"Tool X not found"}}` (HTTP 200, no `result`).

## Hard project rules (from CONTRIBUTING / SECURITY / the PR template, plus code conventions)

- **Never commit or push directly to `main`.** Every change lands via a feature branch + PR — `main` is release-bearing (every push to it runs `.github/workflows/release.yml`), and the only direct writer is the release workflow's own `chore(release)` commit.
- **Anything that weakens the sandbox is out of scope** — never add `fetch`, `import`, filesystem, env, or subprocess access to the sandbox surface, and never let authenticated HTTP serving run user code in-process. Sandbox-escape reports go to a private GitHub Security Advisory, never a public issue.
- **No downloads through the SDK.** Document PDFs, bulk files, PTAB file URIs and `search/download` CSV endpoints stay out of the `methods` tables; return URLs instead.
- **No shared keys.** USPTO keys are personal; never add a path where one person's key serves other people.
- The public API (three tools; `odp.*`/`tsdr.*` globals) is the contract; breaking it needs a major version bump and migration note once released.
- PR checklist beyond the four gates: HTTP-visible change → add a case to `test/http-integration.spec.ts`; sandbox-visible change → add a positive AND a negative case to `test/sandbox.spec.ts` (both runners via `describe.each`); new SDK method → corpus endpoint entry (with a runnable example) in the owning `schema/*.json`, a `methods`-table registration, a row in `test/dispatch.spec.ts` (which asserts it covers every method), and `node scripts/gen-sdk-reference.mjs`.
- ESM everywhere: relative imports use the `.js` extension even in `.ts` sources.
- Logs go to stderr only (`src/util/logger.ts`) — stdout is reserved for stdio JSON-RPC; a stray `console.log` in server code corrupts the protocol stream.

## Test conventions

- HTTP mocking is undici `MockAgent` injected via the `dispatcher` config field on `HttpClient`/`SourceConfig` — never `setGlobalDispatcher`. A new client that doesn't thread `dispatcher` through will silently make real network calls in tests.
- `test/helpers.ts` builds `SourceConfig` (`sourceCfg({ odpKey, tsdrKey, dispatcher })`) and `SupervisorConfig` (`supervisorCfg()`, gates at 1000/s so tests don't wait). Use it instead of literal configs.
- No `vi.mock`/`vi.fn`/fake timers anywhere; the pattern is hand-written fakes satisfying the DI interfaces (`SandboxRunner`, `RpcBridge`, `PreflightLimiter`, `UpstreamGateLike`). Follow it.
- No vitest globals and no setup files — every spec imports `describe/it/expect` from `vitest` explicitly. `pool: 'forks'` is required (sandbox runners spawn processes).
- `test/http-integration.spec.ts` is the canonical end-to-end check, and covers both eras: stateless `2026-07-28` requests (with the `_meta` envelope and `Mcp-Method`/`Mcp-Name` headers) and the legacy `initialize` fallback. Its `rpc()` helper builds the modern shape (and takes a `signal` for disconnect tests); use `post()` for raw/legacy bodies. `fetch` cannot set `Host` (forbidden header): Host tests use raw `node:http`.
- Auth tests sign real ES256 tokens against a local JWKS server (`jose`); keep negative cases (wrong key/issuer/audience, no exp, expired, no sub, missing scope).
- `test/official-client.spec.ts` drives the server with the real `@modelcontextprotocol/client` SDK, including an `execute` → sandbox → `odp` → MockAgent round trip and the `isError`/`structuredContent`/`outputSchema` contract. Keep it passing when touching the transport.
- **MCP Inspector cannot exercise the 2026-07-28 path** (its CLI always drives the legacy leg). For the modern path use the client SDK with `versionNegotiation: { mode: 'auto' }` or `{ mode: { pin: '2026-07-28' } }` — the pin is a **nested object**.
- MockAgent interceptors match exact paths, bodies and query strings; changing serialization surfaces as cryptic "no interceptor" errors, not assertion diffs. `fetch`-based helpers and MockAgent `.delay()` are how timing/serialization tests are written — mutation-check new lifecycle tests (they should fail without the fix).
- `test/live.spec.ts` is skipped unless `USPTO_LIVE=1` and a key are set; it must stay read-only, sequential and small.

## Known traps

- **One request per key.** USPTO blocks concurrent requests with one API key (burst 1) and rate-limits 4–15 req/s; 5M metadata + 1.2M document calls per key per week (reset Sunday 00:00 UTC); wait ≥ 5 s after a 429 (https://data.uspto.gov/apis/api-rate-limits). A 429 can arrive even at one request in flight and the documented rate (observed live) — that is why every 429 pauses the gate and one short retry is allowed. Gates are per process: run one replica, and avoid overlapping old/new instances during deploys.
- **The gate's wake timer is deliberately NOT `unref`'d** while callers wait: a short-lived embedder (script, MCPB host) whose only pending work is a paced call would otherwise exit mid-request. It is cleared as soon as no waiter remains, or tests and processes hang on a long cooldown. `test/http.spec.ts` covers both.
- **Official paths differ from older/third-party specs.** PTAB trial proceedings live at `/api/v1/patent/trials/proceedings/...` (not `/patent/proceedings/...`). Office actions have a current API (`/api/v1/patent/office-action/...`, `odp.officeActions`) and legacy DSAPI datasets (`/api/v1/patent/oa/<dataset>/records`, `odp.oa.*`). `rejectionTypeBag` values are `'101'`, `'102'`, `'103'`, `'112'` (USPTO's own doc sample shows `35 U.S.C. 103`, which matches nothing).
- **Legacy DSAPI (`odp.oa.*`) is different**: POST `application/x-www-form-urlencoded` with a Lucene/Solr `criteria` string plus `start`/`rows` (rows ≤ 1000), its own field names (e.g. `patentApplicationNumber`, digits only), and `{ response: { numFound, docs } }` results. Everything else under `odp` takes the shared JSON search body (`toSearchBody`); `bulk.search` is GET-only (`toSearchQuery`, at most one filter and one rangeFilter — the GET multi-filter separator is undocumented, so it refuses rather than guesses).
- Search POSTs are cached only because they pass `cacheable: true`; the cache key includes the serialized body. Don't mark a non-read POST cacheable.
- `HttpClient` caps bodies at `maxResponseBytes` (default 8 MiB, after bounded gunzip) and its LRU at 32 MiB of text; account-mode clients use a 2 MiB / 100-item cache because up to 500 live at once.
- `LATEST_PROTOCOL_VERSION` / `SUPPORTED_PROTOCOL_VERSIONS` exported by the v2 SDK are the **legacy-era** vocabulary — NOT the revision this server speaks. Use `MCP_PROTOCOL_VERSION` from `src/server/mcpServer.ts`; a test pins `/health` to it.
- Execute limits (`timeoutMs` default 30000 / max 120000, `memoryMb` default 64 / max 256) are per-call Zod defaults on the `execute` tool — NOT env-configurable; don't invent `USPTO_EXEC_*` vars. Byte budgets live in `src/sandbox/limits.ts` (`DEFAULT_LIMITS`). Transport is chosen only by the `--http` flag (account mode additionally by `USPTO_AUTH_PROVIDER=accounts`).
- MCPB packaging: `pnpm build && pnpm mcpb:prepare && pnpm mcpb:pack` produces `uspto-mcp-server.mcpb` (manifest v0.4 from `buildManifest()` in `scripts/mcpb-prepare.mjs`, schema-validated during prepare; `compatibility.runtimes.node >=24.11.0`; keys come from sensitive `user_config`). The prepare step installs from the copied `pnpm-lock.yaml` with `--frozen-lockfile` and MUST keep `--ignore-workspace` (without it pnpm walks up to the repo's `pnpm-workspace.yaml` and `--prod`-prunes the ROOT `node_modules`) and `--config.node-linker=hoisted`. `--ignore-scripts` is fine: isolated-vm loads its prebuilt binary. `bin.ts` treats an unexpanded `${user_config.x}` env value as unset.
- `dist/web/THIRD_PARTY_NOTICES.txt` is emitted by the Vite plugin in `web/third-party-notices.ts` (Rollup `emitFile`, not a file write — the output dir doesn't exist yet in `generateBundle`).
- `dist/` is never cleaned between builds — delete it manually after renaming/moving source files. Never edit `dist/` or `mcpb-build/` (gitignored build artifacts).
- Version strings live in three places (package.json, `src/server/mcpServer.ts`, `src/sdk/bindings.ts` `version()`), currently `0.1.0`. `.github/workflows/release.yml` runs on every push to `main`: gates (the full CI via `workflow_call`) → `cut` (contents: write, `--ignore-scripts`; `scripts/release.mjs` bumps all three — the two source lines carry `x-release-version` markers — writes the CHANGELOG section, builds, packs the tarball, tags, creates the GitHub Release) → `publish` (id-token only, `npm` environment; publishes that exact tarball via npm trusted publishing). With no tags yet, `release.mjs` releases the version package.json already declares, using its hand-written CHANGELOG section. Commit types set the bump (breaking → major, `feat` → minor, anything else → patch); never hand-edit versions or tags. Actions are pinned to commit SHAs (Dependabot updates them). See CONTRIBUTING "Releasing".

## Docs

`docs/architecture.md` (layered design, sandbox, guardrails and rate-limit rationale), `docs/sdk-reference.md` (search syntax, identifiers, errors, and the generated `odp`/`tsdr` method reference), and `docs/accounts.md` (account mode, portal API, key storage) are the deep references.
